# Metadaten {#metadata}

Diese Seite beschreibt die Methoden, die eine Abfrage analysieren, ohne sie auszuführen: die benötigten Parameter, die Struktur ihres Ergebnisses, die geltenden Constraints, ihren analysierten Baum und die Anweisungen, die sie ausführen würde. Verwenden Sie sie, um eine Abfrage zu validieren, ein Formular oder einen Typ für ihre Daten zu erstellen oder das von λORM erzeugte SQL einzusehen.

Diese Methoden greifen nicht auf die Datenbank zu, daher werden keine Verbindungen benötigt: Sie können `orm.init(schema, false)` aufrufen, um das Schema ohne Verbindungsaufbau zu laden.

| Methode | Beschreibung |
|:--|:--|
| `orm.parameters(query)` | Die Variablen, die die Abfrage verwendet (sie gehören in `data`), mit ihren Typen. |
| `orm.model(query)` | Die Eigenschaften des Ergebnisses mit ihren Typen. |
| `orm.constraints(query)` | Die Constraints, die für die Entitäten der Abfrage gelten. |
| `orm.metadata(query)` | Der analysierte Baum der Abfrage: jede Anweisung mit ihrer Entität, ihren Spalten, Parametern und Constraints. |
| `orm.plan(query, options?)` | Wie die Abfrage ausgeführt wird: Dialekt, Quelle und Anweisung jedes Teils. `options.stage` wählt den Stage aus. |
| `orm.normalize(query)` | Die Abfrage in ihrer vollständigen Form, zum Beispiel mit explizit ausgeschriebenen Eigenschaften von `map`. |

Die Abfrage kann eine Lambda-Funktion oder eine Zeichenkette sein. Dieselben Informationen stehen über die [CLI](../cli/index.md) (`lambdaorm parameters`, `model`, `constraints`, `metadata`, `plan`) und über das [Data Gateway](../data-gateway/Rest.md) (`POST /parameters`, `/model`, `/constraints`, `/metadata`, `/plan`) zur Verfügung.

## Beispiel {#example}

```typescript
import { orm } from '@lambdaorm/lib'
import { Orders } from './domain/model' // model generated by `lambdaorm build`

(async () => {
	try {
		// load the schema without connecting to the databases
		await orm.init('./lambdaORM.yaml', false)
		const query = (id: number) => Orders
			.filter(p => p.id === id)
			.include(p => p.details)
			.map(p => ({ name: p.orderDate, customer: p.customer.name }))

		console.log(JSON.stringify(orm.parameters(query), null, 2))
		console.log(JSON.stringify(orm.model(query), null, 2))
		console.log(JSON.stringify(orm.constraints(query), null, 2))
		console.log(JSON.stringify(orm.metadata(query), null, 2))
		console.log(JSON.stringify(orm.plan(query, { stage: 'MySQL' }), null, 2))
	} catch (error: any) {
		console.error(error)
	} finally {
		await orm.end()
	}
})()
```

## Ergebnisse {#results}

Die Ergebnisse enthalten `LambdaOrmParentId`, den internen Schlüssel, mit dem λORM die Positionen ihrer Bestellung zuordnet (siehe [Include](Include.md)).

### Parameter {#parameters}

Die Abfrage benötigt `id`, eine Ganzzahl:

```json
[
  { "name": "id", "type": "integer" },
  {
    "name": "details",
    "type": "Orders.details",
    "children": [
      { "name": "LambdaOrmParentId", "type": "[integer]" }
    ]
  }
]
```

### Modell {#model}

Jede Bestellung im Ergebnis hat `name`, `customer` und das Array `details`:

```json
[
  { "name": "name", "type": "dateTime" },
  { "name": "customer", "type": "string" },
  {
    "name": "details",
    "type": "Orders.details[]",
    "children": [
      { "name": "orderId", "type": "integer" },
      { "name": "productId", "type": "integer" },
      { "name": "unitPrice", "type": "decimal" },
      { "name": "quantity", "type": "decimal" },
      { "name": "discount", "type": "decimal" },
      { "name": "LambdaOrmParentId", "type": "integer" }
    ]
  }
]
```

### Constraints {#constraints}

```json
{
  "entity": "Orders",
  "constraints": [],
  "children": [
    { "entity": "Orders.details", "constraints": [] }
  ]
}
```

### Plan {#plan}

```json
{
  "entity": "Orders",
  "dialect": "MySQL",
  "source": "MySQL",
  "sentence": "SELECT o.OrderDate AS name, c.CompanyName AS customer, o.OrderID AS `__id` FROM Orders o INNER JOIN Customers c ON c.CustomerID = o.CustomerID WHERE o.OrderID = ? ",
  "children": [
    {
      "entity": "Orders.details",
      "dialect": "MySQL",
      "source": "MySQL",
      "sentence": "SELECT o1.OrderID AS orderId, o1.ProductID AS productId, o1.UnitPrice AS unitPrice, o1.Quantity AS quantity, o1.Discount AS discount, o1.OrderID AS LambdaOrmParentId FROM `Order Details` o1  WHERE  o1.OrderID IN (?) "
    }
  ]
}
```

Wenn eine Abfrage Felder einer Beziehung in einer anderen Quelle liest, enthält der Plan zusätzlich `inMemory`, die Schritte, die nach den Anweisungen im Speicher laufen (zum Beispiel `["map", "sort"]`); siehe [Abfragen über Quellen hinweg](CrossSource.md#see-the-plan).
