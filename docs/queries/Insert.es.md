# Insert {#insert}

Esta página muestra cómo insertar registros: con todas las propiedades de la entidad o solo con algunas, junto con entidades relacionadas (`include`), y cómo insertar o actualizar en un solo paso (`upsert`). Para insertar muchos registros a la vez, ver [Inserción masiva](BulkInsert.md). El SQL que se muestra es el generado para MySQL, salvo que se indique otra cosa.

Una consulta se basa tanto en la expresión como en el esquema. Si no se indican las propiedades a insertar, se insertan todas las propiedades de la entidad. Cómo se almacena cada propiedad en cada fuente (nombres de tablas y columnas) lo resuelve el mapping de esa fuente en el esquema.

## Insertar todas las propiedades {#insert-all-the-properties}

Cuando no se indican las propiedades, los datos pasados deben ser un objeto con las propiedades de la entidad.

**Lambda:**

```typescript
Categories.insert()
```

**SQL resultante:**

```sql
INSERT INTO Categories(CategoryName,Description) VALUES(?,?)
```

La clave primaria `id` no se inserta porque es autoincremental: la genera la base de datos.

## Insertar algunas propiedades {#insert-some-properties}

Solo se insertan las propiedades indicadas. Aquí, `name` es una variable de los datos pasados a la consulta.

**Lambda:**

```typescript
Categories.insert({ name: name })
```

**SQL resultante:**

```sql
INSERT INTO Categories(CategoryName) VALUES(?)
```

## Insertar con include {#insert-with-include}

Para insertar un objeto junto con sus objetos relacionados, se incluye la relación. Este ejemplo inserta un pedido y sus detalles; la clave del nuevo pedido se asigna a cada detalle.

**Lambda:**

```typescript
Orders.insert().include(p => p.details)
```

**SQL resultante:**

```sql
-- the order
INSERT INTO Orders(CustomerID,EmployeeID,OrderDate,RequiredDate,ShippedDate,ShipVia,Freight,ShipName,ShipAddress,ShipCity,ShipRegion,ShipPostalCode,ShipCountry)
VALUES(?,?,?,?,?,?,?,?,?,?,?,?,?)

-- each detail of the order
INSERT INTO `Order Details`(OrderID,ProductID,UnitPrice,Quantity,Discount)
VALUES(?,?,?,?,?)
```

## Upsert {#upsert}

`upsert()` inserta el registro o, si ya existe un registro con la misma clave primaria, lo actualiza. Se escribe como un insert: `upsert()` con todas las propiedades, o con las propiedades indicadas. La entidad necesita una clave primaria y los datos deben incluirla (por lo que una clave autoincremental es de poca utilidad aquí).

**Lambda:**

```typescript
// inserts the country, or updates it when one with the same iso3 exists
Countries.upsert()
```

```typescript
await orm.execute('Countries.upsert()', { iso3: 'ARG', name: 'Argentine' }) // inserted
await orm.execute('Countries.upsert()', { iso3: 'ARG', name: 'Argentina' }) // updated: the same row
```

**SQL resultante:**

```sql
-- MySQL / MariaDB
INSERT INTO Countries(iso3,name) VALUES(?,?) ON DUPLICATE KEY UPDATE name = VALUES(name)

-- PostgreSQL
INSERT INTO Countries(iso3,name) VALUES($1,$2)
ON CONFLICT (iso3) DO UPDATE SET name = EXCLUDED.name

-- SQL Server
MERGE INTO Countries WITH (HOLDLOCK) AS t
USING (SELECT 1 AS x) AS s
ON t.iso3 = @iso3
WHEN MATCHED THEN UPDATE SET name = @name
WHEN NOT MATCHED THEN INSERT (iso3,name) VALUES (@iso3,@name);

-- Oracle
MERGE INTO Countries t
USING (SELECT 1 FROM DUAL) s
ON (t.iso3 = :iso3)
WHEN MATCHED THEN UPDATE SET name = :name
WHEN NOT MATCHED THEN INSERT (iso3,name) VALUES (:iso3,:name)

-- SQLite
INSERT INTO Countries(iso3,name) VALUES(?,?) ON CONFLICT DO UPDATE SET name = excluded.name
```

Upsert está disponible en PostgreSQL, MySQL, MariaDB, SQL Server y Oracle (estos dos con `MERGE`, a partir de `@lambdaorm/lib` 3.5.0) y SQLite (a partir de 3.15.0). En SQLite, `ON CONFLICT` sin columnas se aplica a un conflicto en la clave primaria o en cualquier clave única.

!!! warning "Advertencia"
    En MongoDB, upsert todavía no está disponible: falla con el error `upsert is not supported on MongoDB yet`.

Cuando la clave se genera (autoincremental) y no se envía, el upsert inserta. En SQL Server la columna de identidad nunca se inserta (la genera la base de datos) y `OUTPUT INSERTED` la devuelve; el `MERGE` de Oracle no puede devolver valores, por lo que devuelve la clave que se envió.

Upsert es también lo que usa un [update con include](Update.md#update-an-aggregate-composite-relation) de una relación de composición para guardar los hijos.

## Ejemplo de código {#code-example}

Inserta un pedido con dos detalles e imprime el id del nuevo pedido.

```typescript
import { orm } from '@lambdaorm/lib'
import { Orders } from './domain/model' // model generated by `lambdaorm build`

(async () => {
	try {
		await orm.init('./lambdaORM.yaml')
		const order = {
			customerId: 'VINET',
			employeeId: 5,
			orderDate: '1996-07-03T22:00:00.000Z',
			requiredDate: '1996-07-31T22:00:00.000Z',
			shippedDate: '1996-07-15T22:00:00.000Z',
			shipViaId: 3,
			freight: 32.38,
			name: 'Vins et alcools Chevalier',
			address: '59 rue de l-Abbaye',
			city: 'Reims',
			postalCode: '51100',
			country: 'France',
			// orderId is assigned from the new order
			details: [
				{ productId: 11, unitPrice: 14, quantity: 12, discount: 10 },
				{ productId: 42, unitPrice: 9.8, quantity: 10, discount: 10 }
			]
		}
		const query = () => Orders.insert().include(p => p.details)
		// returns the id of the order created
		const result = await orm.execute(query, order)
		console.log(JSON.stringify(result))
	} catch (error: any) {
		console.error(error.stack)
	} finally {
		// releases the connections
		await orm.end()
	}
})()
```
