# Metadados {#metadata}

Esta página descreve os métodos que analisam uma consulta sem executá-la: os parâmetros de que ela precisa, a forma do seu resultado, as restrições que se aplicam, sua árvore analisada e as sentenças que ela executaria. Use-os para validar uma consulta, para construir um formulário ou um tipo para seus dados, ou para ver o SQL que o λORM gera.

Esses métodos não acessam o banco de dados, por isso as conexões não são necessárias: é possível chamar `orm.init(schema, false)` para carregar o esquema sem conectar.

| Método | Descrição |
|:--|:--|
| `orm.parameters(query)` | As variáveis que a consulta usa (que vão em `data`), com seus tipos. |
| `orm.model(query)` | As propriedades do resultado, com seus tipos. |
| `orm.constraints(query)` | As restrições que se aplicam às entidades da consulta. |
| `orm.metadata(query)` | A árvore analisada da consulta: cada sentença com sua entidade, colunas, parâmetros e restrições. |
| `orm.plan(query, options?)` | Como a consulta é executada: o dialeto, a fonte e a sentença de cada parte. `options.stage` seleciona o stage. |
| `orm.normalize(query)` | A consulta em sua forma completa, por exemplo com as propriedades de `map` explicitadas. |

A consulta pode ser uma função lambda ou uma string. As mesmas informações estão disponíveis na [CLI](../cli/index.md) (`lambdaorm parameters`, `model`, `constraints`, `metadata`, `plan`) e no [Data Gateway](../data-gateway/Rest.md) (`POST /parameters`, `/model`, `/constraints`, `/metadata`, `/plan`).

## Exemplo {#example}

```typescript
import { orm } from '@lambdaorm/lib'
import { Orders } from './domain/model' // model generated by `lambdaorm build`

(async () => {
	try {
		// load the schema without connecting to the databases
		await orm.init('./lambdaORM.yaml', false)
		const query = (id: number) => Orders
			.filter(p => p.id === id)
			.include(p => p.details)
			.map(p => ({ name: p.orderDate, customer: p.customer.name }))

		console.log(JSON.stringify(orm.parameters(query), null, 2))
		console.log(JSON.stringify(orm.model(query), null, 2))
		console.log(JSON.stringify(orm.constraints(query), null, 2))
		console.log(JSON.stringify(orm.metadata(query), null, 2))
		console.log(JSON.stringify(orm.plan(query, { stage: 'MySQL' }), null, 2))
	} catch (error: any) {
		console.error(error)
	} finally {
		await orm.end()
	}
})()
```

## Resultados {#results}

Os resultados incluem `LambdaOrmParentId`, a chave interna que o λORM usa para vincular os detalhes ao seu pedido (veja [Include](Include.md)).

### Parâmetros {#parameters}

A consulta precisa de `id`, um inteiro:

```json
[
  { "name": "id", "type": "integer" },
  {
    "name": "details",
    "type": "Orders.details",
    "children": [
      { "name": "LambdaOrmParentId", "type": "[integer]" }
    ]
  }
]
```

### Modelo {#model}

Cada pedido do resultado tem `name`, `customer` e o array `details`:

```json
[
  { "name": "name", "type": "dateTime" },
  { "name": "customer", "type": "string" },
  {
    "name": "details",
    "type": "Orders.details[]",
    "children": [
      { "name": "orderId", "type": "integer" },
      { "name": "productId", "type": "integer" },
      { "name": "unitPrice", "type": "decimal" },
      { "name": "quantity", "type": "decimal" },
      { "name": "discount", "type": "decimal" },
      { "name": "LambdaOrmParentId", "type": "integer" }
    ]
  }
]
```

### Restrições {#constraints}

```json
{
  "entity": "Orders",
  "constraints": [],
  "children": [
    { "entity": "Orders.details", "constraints": [] }
  ]
}
```

### Metadados {#metadata_1}

Uma sentença para os pedidos e, como sua filha, uma para os detalhes (campos `pos` omitidos):

```json
{
  "classtype": "Sentence",
  "name": "select",
  "type": "any",
  "entity": "Orders",
  "alias": "o",
  "clause": "select",
  "columns": [
    { "name": "name", "type": "dateTime" },
    { "name": "customer", "type": "string" },
    { "name": "__id", "type": "integer" }
  ],
  "parameters": [{ "name": "id", "type": "integer" }],
  "constraints": [],
  "values": [],
  "defaults": [],
  "children": [
    {
      "classtype": "Sentence",
      "name": "select",
      "type": "any",
      "entity": "Orders.details",
      "alias": "o1",
      "clause": "select",
      "columns": [
        { "name": "orderId", "type": "integer" },
        { "name": "productId", "type": "integer" },
        { "name": "unitPrice", "type": "decimal" },
        { "name": "quantity", "type": "decimal" },
        { "name": "discount", "type": "decimal" },
        { "name": "LambdaOrmParentId", "type": "integer" }
      ],
      "parameters": [{ "name": "LambdaOrmParentId", "type": "any" }],
      "constraints": [],
      "values": [],
      "defaults": [],
      "children": []
    }
  ]
}
```

### Plano {#plan}

```json
{
  "entity": "Orders",
  "dialect": "MySQL",
  "source": "MySQL",
  "sentence": "SELECT o.OrderDate AS name, c.CompanyName AS customer, o.OrderID AS `__id` FROM Orders o INNER JOIN Customers c ON c.CustomerID = o.CustomerID WHERE o.OrderID = ? ",
  "children": [
    {
      "entity": "Orders.details",
      "dialect": "MySQL",
      "source": "MySQL",
      "sentence": "SELECT o1.OrderID AS orderId, o1.ProductID AS productId, o1.UnitPrice AS unitPrice, o1.Quantity AS quantity, o1.Discount AS discount, o1.OrderID AS LambdaOrmParentId FROM `Order Details` o1  WHERE  o1.OrderID IN (?) "
    }
  ]
}
```

Quando uma consulta lê campos de uma relação em outra fonte, o plano também tem `inMemory`, os passos executados em memória depois das sentenças (por exemplo `["map", "sort"]`); veja [Consultas entre fontes](CrossSource.md#see-the-plan).
