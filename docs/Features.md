# Features

An overview of what λORM does today, with links to the pages that describe each feature.

## Sources

- Databases: MySQL, MariaDB, PostgreSQL, SQL Server, Oracle, MongoDB and SQLite (through sql.js, dialect `SQLjs`).
- [A REST API as a source](schema/HttpSource.md): the dialect `Http`, with OAuth2 client credentials and headers
  forwarded from the context of the caller.
- One query can involve several sources, even of different engines; the
  [stages](schema/SchemaExample-MultiplesStages.md) decide where each entity is stored.
- [Engines](schema/Engines.md): what differs between them (types, empty strings, `upsert`, …).

## Query language

- A [query language](queries/Query-Language.md) based on JavaScript lambda expressions, written as TypeScript code or
  as a string.
- [Select](queries/Select.md), [insert](queries/Insert.md), [bulk insert](queries/BulkInsert.md),
  [update](queries/Update.md) and [delete](queries/Delete.md).
- Implicit [joins](queries/Join.md) and [grouping](queries/Grouping.md).
- Eager loading of relations with [include](queries/Include.md), also across databases: one query per relation, never
  one per row.
- [Queries across sources](queries/CrossSource.md): filter, map, group and sort by fields of relations stored in other
  sources.
- [JSON paths, vectors and points](queries/JsonVectorsPoints.md): `p.meta.address.zip` and `jsonSet`;
  `cosineDistance`, `l2Distance` and `innerProduct` for similarity search (RAG); `distance` in meters, `within` and
  `inside` (a polygon) for geography.
- [Operators and functions](queries/operatorsAndFunctions/OperatorsAndFunctions.md).
- [Query metadata](queries/Metadata.md): the parameters, model, constraints and execution plan of a query, without
  running it.

## Writes

- Inserts with their children (`Orders.insert().include(p => p.details)`), [bulk insert](queries/BulkInsert.md),
  `upsert`, `bulkMerge` and `bulkDelete`.
- `update` and `delete` answer the number of affected rows: 0 means not found, or a conflict with optimistic locking.
- `update().include()` of a composite relation saves the whole aggregate.

## Usage

- [Usage examples](usage/Usage.md): a single source, several sources, CQRS and the Node.js client.
- [Repositories](usage/Repository.md), generated by `lambdaorm build` and extended with your own methods.
- [Transactions](usage/Transaction.md) across sources and stages.
- [Scripts](usage/Script.md): a whole use case (variables, conditions, loops and several queries) in one transaction,
  also over the Data Gateway.
- [Changes of the data and outbox](usage/DataEvents.md): `orm.onDataChange` after each commit, and an outbox written
  in the same transaction.
- [Typed queries](usage/TypedQueries.md): queries with a name in the schema and the types of their results.

## Schema

- A [schema](schema/Schema.md) in YAML or JSON that decouples the domain from the infrastructure.
- [Mappings](schema/SchemaDefinition.md) between the domain and the databases, and
  [entity inheritance](schema/SchemaExample-Extend.md) (`extends`).
- [Environment variables](schema/SchemaDefinition-EnvironmentVariables.md) for connections and secrets.
- Indexes, unique keys, constraints, default values and computed properties, written as
  [expressions](schema/SchemaDefinition-Expressions.md) of [3xpr](https://www.npmjs.com/package/3xpr).
- [Stages](schema/SchemaExample-MultiplesStages.md): several infrastructures for the same domain (development,
  production, CQRS).
- [Listeners and subscribers](schema/SchemaExample-Listener.md): awaited, and run in the transaction of the sentence
  that triggers them.

## Access control

- [Views](schema/Views.md): restrict entities and properties, mask them, add computed ones, mark personal data (PII).
- [Context and row filters](schema/Context.md): who runs a query, and the rows each view sees.
- The [Data Gateway](data-gateway/Security.md): credentials with permissions, and an audit of every write.

## Synchronization and migrations

- [Synchronization](schema/SchemaSynchronization.md) between the schema and the databases:
  [push](schema/SchemaSynchronization-Push.md), [pull](schema/SchemaSynchronization-Pull.md),
  [fetch](schema/SchemaSynchronization-Fetch.md) (the drift, with exit code 1 for CI),
  [introspect](schema/SchemaSynchronization-Introspect.md) and
  [incorporate](schema/SchemaSynchronization-Incorporate.md).
- [Migrations](schema/SchemaSynchronization-Migrations.md): the changes that can lose data stop `push` unless they are
  allowed, each change is written with its undo, and `migrate` goes back to a version.
- [Seed](schema/SchemaSynchronization-Seed.md): the data a stage starts with, inserted only where it is missing.

## Performance and operations

- [Bulk insert](queries/BulkInsert.md), and includes that read the keys of each level with `IN`, in chunks run in
  parallel.
- Connection pooling.
- [Observability](schema/Observability.md): logs, metrics and traces with OpenTelemetry.

## Tools and clients

- The [CLI](cli/index.md) (`npm i -g @lambdaorm/cli`, command `lambdaorm`): projects, code generation,
  synchronization, import and export, queries and scripts.
- The [Data Gateway](data-gateway/index.md) (Docker image `flaviorita/data-gateway`):
    - [REST](data-gateway/Rest.md), [WebSocket](data-gateway/WebSocket.md) and [MCP](data-gateway/Mcp.md) for AI
      agents, with several schemas per instance;
    - [credentials with permissions](data-gateway/Security.md), audit of writes, metrics and health checks.
- The [IDE](ide/index.md) of the Data Gateway (Docker or desktop): connections, explorer, entity forms, queries with
  autocompletion, diagrams and administration; its React components are [`@lambdaorm/ui`](ide/Embedding.md).
- [Clients](data-gateway/Clients.md):
    - the Node.js client (`@lambdaorm/client`, REST or WebSocket), with the interface of the library;
    - other languages: generate a client from the Data Gateway's OpenAPI 3 document.
