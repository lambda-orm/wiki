    1.6.2¶

    Patch Changes¶

    • e4ce3af: 3xpr 5.2.0 in every package (one copy of it). lib builds each Orm's 3xpr instance with the ExpressionsBuilder 3xpr now exports, instead of importing it from one of its files.
    • b22e580: lambdaorm --version and lambdaorm version print this CLI's version (they printed the version of the project's package.json in the current directory, or looked for the old lambdaorm-cli package).
    • Updated dependencies [e4ce3af]
    • @lambdaorm/base@3.2.1

    1.6.0¶

    Minor Changes¶

    • 0e683c6: Scripts: several queries in one transaction.

    • client: orm.executeScript(script, data, options) calls the service's POST /script (the service must run with SCRIPT_ENABLED=true).

    • cli: new lambdaorm script command, with the script inline (-x) or in a file (-f), its variables in -d; local with the workspace or on a service with -u.

    • d16b60a: stage.push().sentencesBySource(): the DDL grouped per source (one script per database). cli: lambdaorm push -o <dir> writes one script per source that changes, <stage>.<source>.sql (deterministic names, to rename into a versioned migration); -o without a folder prints the DDL grouped by source — L19.

    Patch Changes¶

    • 2ee8930: Upgrade the data7expressions dependencies to their latest major: 3xpr from 1.x to ^5.1.1, h3lp and typ3s to ^5.0.0 (and json-light to ^5.0.0 in the CLI). No API changes were needed. Behaviour inherited from 3xpr:

    • <= now has the same precedence as the other comparison operators (a <= b == true used to evaluate as a <= (b == true)).

    • 3xpr 5.1.0 evaluates async expressions statement by statement (listeners, orm.execute inside expressions), never runs an async function while building an expression, and adds throw, try/catch, return, break and continue; 3xpr 5.1.1 parses the empty string literal "" (it used to swallow the rest of the expression).

    • ee1e7ac: Packaging:

    • The published exports pointed to ./build/lib/index.js, a path the package doesn't have: require('@lambdaorm/lib') (and base, client) failed for everyone installing from npm. dist now rewrites exports (and bin) like main — L7.

    • cli: declares bin: lambdaorm, so npm i -g @lambdaorm/cli installs the lambdaorm command — L29.

    • Every package's dist is smoke-tested before it can be released: required by its name (so exports applies) and, for the CLI, lambdaorm --help.

    • 8b8f470: Stage commands:

    • push/DDL: a stage's last source without condition is a catch-all, as in DML: it gets only the entities no other source took (it used to receive every entity) — L25.

    • fetch/pull on PostgreSQL work with reserved words as column names (order): the metadata query quoted the column twice — L6, L21.
    • stage.fetch() reports the drift: per mapping, the entities that differ from the model (present in one side only, different columns, types, lengths, required, primary key), each with its differences; no entities when in step. stage.read() returns the databases' mappings as fetch did (pull uses it) — L22.

    • cli: lambdaorm fetch exits with code 1 when there are differences (for CI). fetch, pull, schema, introspect and incorporate load the --envfile they declared (it was ignored).
