    Definição¶

    Esta página é a referência do arquivo do esquema (lambdaORM.yaml): sua estrutura e todas as chaves de suas seções domain, application e infrastructure, com um exemplo para cada uma.

    O esquema contém toda a configuração de que o ORM precisa. Ele separa o modelo de negócio (domain) da persistência dos dados (infrastructure):

    • No domínio, as entidades e os enums que representam o modelo de negócio são completamente limpos, sem nenhum atributo que os acople à persistência.
    • Todas as consultas são escritas sobre o modelo de negócio, de modo que ficam desacopladas do modelo físico dos dados.
    • Na infraestrutura, define-se tudo o que é necessário para armazenar e ler os dados nas diferentes fontes.

    O esquema pode ser escrito em um arquivo YAML ou JSON, ou passado como um objeto quando o ORM é inicializado (veja Uso do esquema).

    Todas as expressões usadas para definir condições e ações são avaliadas pelo mecanismo de expressões 3xpr (veja Expressões no esquema), e qualquer valor pode vir de uma variável de ambiente (veja Variáveis de ambiente).

    Estrutura¶

    domain:
  enums:
    - name: string
      extends: string
      abstract: boolean
      values:
        - name: string
          value: any
  entities:
    - name: string
      abstract: boolean
      extends: string
      singular: string
      view: boolean
      primaryKey: string[]
      uniqueKey: string[]
      required: string[]
      properties:
        - name: string
          type: string | integer | decimal | boolean | dateTime | date | time | json
          length: number
          required: boolean
          autoIncrement: boolean
          view: boolean
          enum: string
          key: string
          default: expression
          readExp: expression
          readValue: expression
          writeValue: expression
      indexes:
        - name: string
          fields: string[]
      relations:
        - name: string
          type: oneToMany | manyToOne | oneToOne
          from: string
          entity: string
          to: string
          composite: boolean
          weak: boolean
          target: string
      constraints:
        - message: string
          condition: expression
application:
  start:
    - name: string
      condition: expression
      expression: expression
  end:
    - name: string
      condition: expression
      expression: expression
  listeners:
    - name: string
      on: [select | insert | upsert | update | delete]
      condition: expression
      before: expression
      after: expression
      error: expression
      transactional: boolean
infrastructure:
  mappings:
    - name: string
      extends: string
      entities:
        - name: string
          mapping: string
          abstract: boolean
          extends: string
          sequence: string
          filter: expression
          properties:
            - name: string
              mapping: string
              readMappingExp: expression
              dbType: string
              previousMapping: string
  sources:
    - name: string
      dialect: MySQL | MariaDB | PostgreSQL | Oracle | SqlServer | MongoDB | SQLjs
      mapping: string
      connection: object | environment variable
  stages:
    - name: string
      sources:
        - name: string
          condition: expression
  views:
    - name: string
      entities:
        - name: string
          exclude: boolean
          properties:
            - name: string
              exclude: boolean
              readExp: expression
  paths:
    src: string
    state: string
    domain: string
  queue:
    config: object
    consumers:
      - name: string
        config: object
        subscribe: object
        execute: expression

    Seções principais¶

    Chave Descrição
    domain O modelo de negócio: enums e entidades.
    application Tarefas executadas quando o ORM inicia e termina, e listeners.
    infrastructure Como e onde os dados são armazenados: mapeamentos, fontes, stages, views.

    Domínio¶

    Chave Descrição
    enums Os enums do modelo.
    entities As entidades do modelo.
    • Um enum pode ser usado como tipo de uma propriedade.
    • Uma entidade é definida com suas propriedades, relações, chaves, índices e restrições.

    Enum¶

    Um enum define um conjunto de valores que pode então ser usado como tipo de uma propriedade.

    Chave Descrição Obrigatória
    name Nome do enum. sim
    values Valores do enum (name e value). sim
    extends Nome de outro enum cujos valores este enum herda.
    abstract O enum é usado apenas como base para outros enums.

    Quando um valor não tem value, seu name é usado.

    Exemplo de enum¶

    Neste exemplo, o enum DeviceType é definido e usado como tipo da propriedade type da entidade Devices.

    domain:
  enums:
    - name: DeviceType
      values:
        - name: phone
          value: phone
        - name: computer
          value: computer
        - name: robot
          value: robot
  entities:
    ...
    - name: Devices
      extends: Products
      primaryKey: ["id"]
      uniqueKey: ["name"]
      properties:
        - name: id
          length: 32
          required: true
          default: 'concat(type,"-",switch(type){case"phone":imei;default:mac;})'
        - name: type
          length: 16
          required: true
          enum: DeviceType
        - name: name
          length: 32
          required: true
    ...

    Entidade¶

    Uma entidade é definida com suas propriedades, relações e restrições.

    Chave Descrição Obrigatória
    name Nome da entidade. Um nome com ponto (Orders.details) define uma entidade composta. sim
    properties Propriedades da entidade. sim
    abstract A entidade é usada apenas como base para outras entidades (nenhuma tabela é criada para ela).
    extends Nome da entidade cujas propriedades, chave primária e relações esta entidade herda.
    singular Nome no singular, usado nas classes geradas por lambdaorm build (por padrão, é deduzido do nome).
    view A entidade é uma view: o push não cria tabela para ela (veja abaixo).
    primaryKey Propriedades da chave primária.
    uniqueKey Propriedades da chave única.
    required Propriedades obrigatórias (o mesmo que required: true em cada uma delas).
    indexes Índices (name e fields).
    relations Relações com outras entidades.
    constraints Restrições validadas quando um registro é gravado.

    As propriedades da chave primária e da chave única são obrigatórias, a menos que indiquem o contrário.

    Abstract e extends na entidade¶

    Neste exemplo, a entidade abstrata Positions é definida, e a entidade Countries a estende: Countries recebe as propriedades latitude e longitude.

    domain:
  entities:
    - name: Positions
      abstract: true
      properties:
        - name: latitude
          length: 16
        - name: longitude
          length: 16
    - name: Countries
      extends: Positions
      primaryKey: ["iso3"]
      uniqueKey: ["name"]
      properties:
        - name: name
          required: true
        - name: iso3
          length: 3
          required: true

    Uma entidade não precisa ser abstrata para ser estendida. Veja Extend.

    Definir a entidade como view¶

    Este exemplo define a entidade Users como view, porque sua tabela é gerenciada por um sistema externo. O push não cria tabela para uma entidade view, e os comandos de stage não a alteram.

    domain:
  entities:
    ...
    - name: Users
      view: true
      extends: Basics
      primaryKey: ["username"]
      uniqueKey: ["email"]
      properties:
        - name: username
          length: 32
          required: true
        - name: firstname
          required: true
        - name: lastname
    ...

    Propriedade¶

    Chave Descrição Obrigatória Padrão
    name Nome da propriedade. sim
    type Tipo da propriedade (veja Tipos de propriedade). string
    length Comprimento de uma propriedade string. veja abaixo
    required A propriedade não pode ser nula. false
    autoIncrement O valor é gerado pelo banco de dados. false
    enum Nome do enum ao qual o valor deve pertencer.
    view A propriedade não é armazenada: seu valor vem de readExp. false
    default Expressão avaliada pelo λORM para definir o valor quando um registro é inserido.
    readExp Expressão de leitura, resolvida na fonte (banco de dados).
    readValue Expressão avaliada pelo λORM sobre o valor lido da fonte.
    writeValue Expressão avaliada pelo λORM sobre o valor antes de ser gravado.
    key Valor fixo usado para filtrar leituras e atualizações, e atribuído na inserção.

    Tipos de propriedade¶

    Tipo Valor em Node Coluna criada pelo push (por padrão)
    string string VARCHAR(length); sem length: TEXT no PostgreSQL, VARCHAR(80) nos demais mecanismos
    integer number INTEGER (Oracle NUMBER(10))
    decimal number DECIMAL(10,4) (Oracle NUMBER(19,4))
    boolean boolean BOOLEAN (SqlServer BIT, Oracle CHAR(1))
    dateTime Date TIMESTAMP (PostgreSQL), DATETIME (MySQL, MariaDB, SqlServer), DATE (Oracle)
    date Date DATE (SqlServer SMALLDATETIME)
    time Date TIME (Oracle DATE)
    json objeto ou lista JSONB (PostgreSQL), JSON (MySQL, MariaDB), NVARCHAR(MAX) (SqlServer), CLOB (Oracle), TEXT (outros)
    • json: objetos e listas são gravados e lidos como tais (não é necessário chamar JSON.stringify nem JSON.parse).
    • dateTime: no PostgreSQL, o valor é gravado com milissegundos e seu deslocamento, de modo que uma coluna timestamptz (veja dbType em Mapeamento de propriedade) preserva o instante exato.
    • string sem comprimento: no PostgreSQL é ilimitada (TEXT); nos demais mecanismos é VARCHAR(80), então defina length quando um valor puder ser mais longo.
    • '', 0 e false são valores, nunca NULL (o Oracle é a exceção: ele armazena '' como NULL).

    Veja também Mecanismos de banco de dados para as diferenças entre os mecanismos.

    Neste exemplo, name não tem comprimento, settings é um objeto JSON e createdAt uma data e hora:

    domain:
  entities:
    - name: Products
      primaryKey: ["id"]
      properties:
        - name: id
          length: 36
          required: true
        - name: name                # TEXT on PostgreSQL, VARCHAR(80) elsewhere
          required: true
        - name: settings
          type: json                # { "color": "red", "tags": ["a", "b"] } in and out as an object
        - name: createdAt
          type: dateTime

    Definir a propriedade como view e readExp¶

    Uma propriedade view não é armazenada no banco de dados (o push não cria coluna para ela): seu valor é calculado na leitura, com a expressão em readExp. Neste exemplo, fullName é construída a partir de lastname e firstname.

    domain:
  entities:
    ...
    - name: Users
      extends: Basics
      primaryKey: ["username"]
      uniqueKey: ["email"]
      properties:
        - name: username
          length: 32
          required: true
        - name: firstname
          required: true
        - name: lastname
          required: true
        - name: fullName
          view: true
          readExp: concat(lastname,", ",firstname)
    ...

    readExp também pode ser definida em uma propriedade armazenada: a expressão é aplicada na leitura, e nada muda na gravação.

    Valor padrão na propriedade¶

    Quando um registro é inserido sem valor para a propriedade, a expressão em default é avaliada pelo λORM (não pelo banco de dados) e seu resultado é gravado. Neste exemplo, o id de um grupo é construído a partir de seu nome.

    domain:
  entities:
    - name: Groups
      extends: Basics
      primaryKey: ["id"]
      uniqueKey: ["name"]
      properties:
        - name: id
          length: 32
          default: lower(substring(replace(name," ","-"),0,32))
          required: true
        - name: name
          length: 32
          required: true

    Valor de leitura e gravação na propriedade¶

    readValue e writeValue são avaliadas pelo λORM: writeValue transforma o valor antes de ser gravado, e readValue transforma o valor lido do banco de dados. Neste exemplo, o e-mail é armazenado criptografado e retornado descriptografado; a chave vem de uma variável de ambiente.

    domain:
  entities:
    ...
    - name: Users
      extends: Basics
      primaryKey: ["username"]
      uniqueKey: ["email"]
      properties:
        - name: username
          length: 32
          required: true
        - name: email
          required: true
          length: 255
          writeValue: encrypt(lower(email),"${USERS_SECRET_KEY}")
          readValue: decrypt(email,"${USERS_SECRET_KEY}")
    ...

    Valor de chave na propriedade¶

    O valor definido em key é usado como filtro nas consultas de leitura, atualização e exclusão, e é atribuído à propriedade quando um registro é inserido.

    Isso é útil para definir várias entidades sobre a mesma tabela ou coleção. Neste exemplo, uma tabela Locations armazena países, estados e cidades, e cada um é tratado como uma entidade separada:

    domain:
  entities:
    - name: Locations
      abstract: true
      primaryKey: ["type","code"]
      uniqueKey: ["type","name"]
      properties:
        - name: code
          required: true
          length: 16
        - name: type
          required: true
          length: 16
        - name: name
          required: true
    - name: Countries
      extends: Locations
      properties:
        - name: type
          key: 'country'
    - name: States
      extends: Locations
      properties:
        - name: type
          key: 'state'
    - name: Cities
      extends: Locations
      properties:
        - name: type
          key: 'city'
infrastructure:
  mappings:
    - name: default
      entities:
        - name: Locations
          abstract: true
          mapping: TBL_LOCATIONS
          properties:
            - name: code
              mapping: CODE
            - name: type
              mapping: TYPE
            - name: name
              mapping: NAME
        - name: Countries
          extends: Locations
        - name: States
          extends: Locations
        - name: Cities
          extends: Locations

    Relação¶

    Chave Descrição Obrigatória Padrão
    name Nome da relação. sim
    from Propriedade desta entidade. sim
    entity Entidade relacionada. sim
    to Propriedade da entidade relacionada. sim
    type Tipo da relação (veja abaixo). oneToMany
    composite Os registros relacionados fazem parte desta entidade (veja Entidade composta). false
    weak O push não cria chave estrangeira para a relação (por exemplo, entre entidades em fontes diferentes). false
    target Nome da relação inversa criada na entidade relacionada.

    O tipo da relação determina o que ela retorna:

    Tipo Significado Retorna
    oneToMany Muitos registros desta entidade referenciam um registro de entity. um objeto
    manyToOne Muitos registros de entity referenciam este registro. uma lista
    oneToOne Um registro desta entidade se relaciona com um registro de entity. um objeto

    Relações manyToOne são sempre fracas (weak).

    Relação target¶

    Com target, a relação inversa é criada na entidade relacionada. Por exemplo, se a entidade DeviceStatuses tem uma relação com Devices com target: statuses, uma relação chamada statuses é criada em Devices. O tipo da relação target depende do tipo da relação de origem:

    Origem Target
    oneToMany manyToOne
    oneToOne oneToOne 
    domain:
  entities:
    - name: DeviceStatuses
      extends: Basics
      primaryKey: ["id"]
      indexes:
        - name: time
          fields: ["time"]
      properties:
        - name: id
          type: integer
          required: true
          autoIncrement: true
        - name: deviceId
          length: 32
          required: true
        - name: time
          type: dateTime
      relations:
        - name: device
          from: deviceId
          entity: Devices
          to: id
          target: statuses

    Restrição¶

    Chave Descrição Obrigatória
    message Mensagem retornada quando falha. sim
    condition Expressão booleana a avaliar. sim

    As restrições são expressões avaliadas pelo λORM quando um registro é inserido ou atualizado. O ORM também cria restrições a partir de outras definições, por exemplo:

    • Uma propriedade obrigatória recebe uma restrição que verifica que ela não é nula.
    • Uma propriedade cujo tipo é um enum recebe uma restrição que verifica que o valor pertence ao enum.

    Você pode adicionar suas próprias restrições com uma message e uma condition: quando a condição não é atendida, a gravação falha com a mensagem. Neste exemplo, são validados o formato do e-mail e a ordem de duas datas:

    domain:
  entities:
    - name: Users
      properties:
        ...
        - name: email
          required: true
          length: 255
          writeValue: encrypt(lower(email),"${USERS_SECRET_KEY}")
          readValue: decrypt(email,"${USERS_SECRET_KEY}")
      constraints:
        - message: invalid email
          condition: test(email,"^\w+([\.-]?\w+)*@\w+([\.-]?\w+)*(\.\w{2,3})+$")
    - name: Files
      properties:
        - name: id
          length: 255
          required: true
        - name: type
          length: 16
          required: true
          enum: FileType
        - name: deviceId
          length: 32
          required: true
        - name: startDate
          type: dateTime
          required: true
        - name: endDate
          type: dateTime
          required: true
      constraints:
        - message: endDate cannot be less than startDate
          condition: startDate<=endDate

    Aplicação¶

    Chave Descrição
    start Tarefas executadas quando o ORM é inicializado (orm.init()).
    end Tarefas executadas quando o ORM é encerrado (orm.end()).
    listeners Expressões executadas antes ou depois de uma consulta, ou quando ela falha.

    Tarefa¶

    Cada tarefa de start e end tem:

    Chave Descrição Obrigatória
    name Nome da tarefa. sim
    expression Expressão a executar. sim
    condition A tarefa só é executada quando esta expressão é verdadeira.

    Listener¶

    Chave Descrição Obrigatória Padrão
    name Nome do listener. sim
    on Categorias de consulta que o disparam: select, insert, upsert, update, delete. sim
    condition O listener só é executado quando esta expressão é verdadeira.
    before Expressão executada antes da consulta.
    after Expressão executada depois da consulta.
    error Expressão executada quando a consulta falha.
    transactional false executa o listener fora da transação da consulta. true

    Veja Listener para saber como os listeners são executados e os argumentos que recebem.

    Infraestrutura¶

    Chave Descrição
    mappings Como as entidades são mapeadas para as tabelas ou coleções dos bancos de dados.
    sources Os bancos de dados e suas conexões.
    stages Cenários que decidem de qual fonte cada entidade é lida e em qual é gravada.
    views Views que restringem ou modificam os resultados das consultas.
    paths Pastas onde os arquivos gerados e o estado do ORM são gravados.
    queue Fila Kafka, usada pelo Data Gateway.

    Quando algumas delas são omitidas, o λORM as completa:

    • Sem mappings, é criado um mapeamento vazio (com o nome da fonte quando há apenas uma fonte).
    • Uma fonte sem mapping usa o primeiro mapeamento.
    • Sem stages, é criado um stage chamado default com a primeira fonte.
    • Sem views, é criada uma view chamada default sem restrições.

    Mapeamento¶

    Um mapeamento define como as entidades são armazenadas nas tabelas ou coleções de um banco de dados. Entidades e propriedades que não estão listadas são mapeadas para uma tabela ou coluna com o mesmo nome.

    Chave Descrição Obrigatória
    name Nome do mapeamento. sim
    entities Mapeamentos de entidade.
    extends Nome de um mapeamento cujos mapeamentos de entidade este herda.

    Mapeamento de entidade¶

    Chave Descrição Obrigatória Padrão
    name Nome da entidade. sim
    mapping Nome da tabela ou coleção no banco de dados. o nome da entidade
    abstract O mapeamento de entidade é usado apenas como base para outros.
    extends Nome do mapeamento de entidade do qual este herda.
    sequence Nome da sequência usada para gerar os valores.
    filter Expressão que filtra os registros da tabela.
    properties Mapeamentos de propriedade.
    Abstract e extends no mapeamento de entidade¶

    Mapeamentos de entidade abstratos são úteis como base para outros mapeamentos de entidade. Este exemplo define o mapeamento de entidade abstrato Locations, e as entidades concretas o estendem, de modo que as três são armazenadas na tabela TBL_LOCATIONS.

    ...
infrastructure:
  mappings:
    - name: default
      entities:
        - name: Locations
          abstract: true
          mapping: TBL_LOCATIONS
          properties:
            - name: code
              mapping: CODE
            - name: type
              mapping: TYPE
            - name: name
              mapping: NAME
        - name: Countries
          extends: Locations
        - name: States
          extends: Locations
        - name: Cities
          extends: Locations
...
    Filtro no mapeamento de entidade¶

    O filtro de um mapeamento de entidade é aplicado a todas as consultas da entidade. Este exemplo lê os usuários da tabela user_entity que pertencem a um determinado realmId.

    ...
infrastructure:
  mappings:
    - name: default
    - name: keycloak
      entities:
        - name: Users
          mapping: user_entity
          filter: realmId == "${REALM_ID}"
          properties:
            - name: username
              mapping: username
            - name: firstname
              mapping: first_name
            - name: lastname
              mapping: last_name
            - name: email
              mapping: email
            - name: created
              mapping: created_timestamp
              readMappingExp: millisecondToDate(created/1000)
            - name: realmId
              length: 255
              mapping: realm_id
...

    Mapeamento de propriedade¶

    Chave Descrição Obrigatória Padrão
    name Nome da propriedade. sim
    mapping Nome da coluna no banco de dados. o nome da propriedade
    readMappingExp Expressão de leitura, resolvida na fonte.
    dbType Tipo de coluna usado pelo push (DDL), em vez do deduzido a partir do tipo da propriedade.
    previousMapping Nome anterior da coluna: o push renomeia a coluna em vez de adicionar uma nova.
    Tipo de coluna no mapeamento de propriedade¶

    dbType define o tipo de coluna usado por todo DDL que cria ou altera a coluna (push, push -o). Use-o para escolher um tipo que o tipo da propriedade sozinho não fornece, por exemplo um instante com milissegundos ou um JSON binário no PostgreSQL:

    infrastructure:
  mappings:
    - name: catalog
      entities:
        - name: Products
          mapping: products
          properties:
            - name: settings
              mapping: settings
              dbType: jsonb
            - name: createdAt
              mapping: created_at
              dbType: timestamptz(3)
    Renomear uma coluna com previousMapping¶

    Para renomear uma coluna sem perder seus dados, defina o novo nome em mapping e o atual em previousMapping. O push então gera ALTER TABLE … RENAME COLUMN icon TO icon_name (SqlServer sp_rename) em vez de adicionar uma nova coluna.

    infrastructure:
  mappings:
    - name: catalog
      entities:
        - name: Categories
          mapping: categories
          properties:
            - name: icon
              mapping: icon_name
              previousMapping: icon

    Remova previousMapping quando a renomeação tiver sido aplicada em todos os bancos de dados. Renomear uma tabela não é suportado.

    Expressão de leitura no mapeamento de propriedade¶

    A expressão em readMappingExp é resolvida na fonte, e seu resultado é retornado nas consultas de leitura. Neste exemplo, a coluna created_timestamp, armazenada em milissegundos, é retornada como data:

    infrastructure:
  mappings:
    - name: default
    - name: keycloak
      entities:
        - name: Users
          mapping: user_entity
          filter: realmId == "${REALM_ID}"
          properties:
            ...
            - name: created
              mapping: created_timestamp
              readMappingExp: millisecondToDate(created/1000)
            - name: realmId
              length: 255
              mapping: realm_id
...

    Fonte¶

    Uma fonte é um banco de dados e sua conexão.

    Chave Descrição Obrigatória Padrão
    name Nome da fonte. sim
    dialect Dialeto: MySQL, MariaDB, PostgreSQL, Oracle, SqlServer, MongoDB ou SQLjs. sim
    mapping Nome do mapeamento usado pela fonte. o primeiro mapeamento
    connection Conexão: um objeto ou uma variável de ambiente que a contém. sim

    Definir a conexão na fonte¶

    A conexão pode ser definida com uma variável de ambiente ou diretamente no esquema. Escrevê-la no esquema não é recomendado, por questões de segurança e porque a conexão normalmente muda de um ambiente para outro; faça isso apenas em um teste local temporário.

    Usando uma variável de ambiente:

    ...
infrastructure:
  sources:
    - name: test
      dialect: MySQL
      mapping: test
      connection: ${CNN_MYSQL}
...

    No esquema:

    ...
infrastructure:
  sources:
    - name: test
      dialect: MySQL
      mapping: test
      connection:
        host: localhost
        port: 3306
        user: test
        password: test
        database: test
...

    Stage¶

    Um stage é um cenário: suas regras decidem qual fonte cada entidade usa. Uma consulta é executada no stage indicado em suas opções; sem ele, é executada no primeiro stage.

    Chave Descrição Obrigatória
    name Nome do stage. sim
    sources Regras de fonte. sim

    Regra de fonte¶

    Chave Descrição Obrigatória Padrão
    name Nome da fonte. sim
    condition Expressão booleana que seleciona a fonte. true

    Condição na regra de fonte¶

    condition decide em qual fonte uma consulta ou uma sentença DDL é executada. As variáveis disponíveis na expressão são:

    Variável Descrição Valor
    entity Entidade da sentença nome da entidade
    action Ação da sentença select, insert, bulkInsert, update, upsert, delete, createEntity, …
    category Categoria da sentença select, insert, upsert, update, delete, create, alter, drop, …
    type Tipo da sentença dql, dml, ddl
    read A sentença lê booleano
    write A sentença grava booleano
    dml A sentença é uma consulta (DQL ou DML) booleano
    ddl A sentença é DDL booleano

    As regras são avaliadas na ordem em que são definidas, e é usada a primeira fonte cuja condição seja verdadeira.

    No exemplo a seguir, a entidade Users usa a fonte keycloak, e todas as outras entidades usam a fonte main.

    ...
infrastructure:
  stages:
    - name: default
      sources:
        - name: main
          condition: entity != "Users"
        - name: keycloak
          condition: entity == "Users"

    Fonte coringa¶

    Uma regra de fonte sem condition é uma fonte coringa (catch-all): como prevalece a primeira fonte que corresponde, ela recebe apenas as entidades que nenhuma fonte anterior recebeu. Isso se aplica tanto às consultas (DML) quanto ao push e aos demais comandos de stage (DDL), de modo que a fonte coringa não recebe as tabelas das entidades atribuídas a outras fontes. Coloque-a por último.

    infrastructure:
  stages:
    - name: default
      sources:
        - name: keycloak
          condition: entity == "Users"
        - name: main

    View¶

    Uma view restringe ou modifica os resultados das consultas. Uma consulta usa a view indicada na opção view; entidades não listadas em uma view não têm restrições.

    Chave Descrição Obrigatória
    name Nome da view. sim
    entities Views de entidade.

    No exemplo a seguir, a view default mascara apiKey e oculta email, a view collector não pode acessar usuários e grupos, e a view admin pode acessar tudo.

    infrastructure:
  views:
    - name: default
      entities:
        - name: Devices
          properties:
            - name: apiKey
              readExp: '"***"'
        - name: Users
          properties:
            - name: created
              readExp: date(created)
            - name: email
              exclude: true
    - name: collector
      entities:
        - name: Users
          exclude: true
        - name: Groups
          exclude: true
        - name: GroupUsers
          exclude: true
    - name: admin
      entities: []

    View de entidade¶

    Chave Descrição Obrigatória
    name Nome da entidade. sim
    exclude A entidade não pode ser acessada com esta view.
    properties Views de propriedade.
    Exclude na view de entidade¶

    Uma entidade com exclude não pode ser acessada quando esta view é usada.

    infrastructure:
  views:
    ...
    - name: collector
      entities:
        - name: Users
          exclude: true
        - name: Groups
          exclude: true
        - name: GroupUsers
          exclude: true
    ...

    View de propriedade¶

    Chave Descrição Obrigatória
    name Nome da propriedade. sim
    exclude A propriedade não pode ser acessada com esta view.
    readExp Expressão de leitura, resolvida na fonte.
    Exclude na view de propriedade¶

    Uma propriedade com exclude não pode ser acessada quando esta view é usada.

    infrastructure:
  views:
    - name: default
      entities:
        ...
        - name: Users
          properties:
            - name: created
              readExp: date(created)
            - name: email
              exclude: true
      ...
    Expressão de leitura na view de propriedade¶

    Com readExp, o resultado da expressão é retornado nas consultas de leitura em vez do valor armazenado. Neste exemplo, created é retornada como data, sem a hora:

    infrastructure:
  views:
    - name: default
      entities:
        ...
        - name: Users
          properties:
            - name: created
              readExp: date(created)
      ...

    Paths¶

    Pastas, relativas à pasta do esquema, onde os arquivos gerados e o estado do ORM são gravados.

    Chave Descrição Padrão
    src Pasta do código-fonte. src
    domain Pasta, dentro de src, onde lambdaorm build grava o modelo e os repositórios. domain
    state Pasta do estado do ORM (modelo de cada stage, scripts DDL aplicados pelo push). orm_state 
    infrastructure:
  paths:
    src: src
    domain: domain
    state: orm_state

    Queue¶

    infrastructure.queue configura uma fila Kafka. Ela não é usada pelo próprio @lambdaorm/lib: é lida pelo Data Gateway para execuções enfileiradas, e adiciona a função queue.send(topic, messages) às expressões.

    Chave Descrição
    config Configuração do cliente Kafka (kafkajs).
    consumers Consumidores: cada um tem um name, uma config de consumidor, um subscribe (tópico) e uma expressão execute executada para cada mensagem, com as variáveis message, topic e partition.

    Neste exemplo, cada mensagem do tópico insights-sync é executada no stage insights:

    infrastructure:
  queue:
    config: $QUEUE_CONFIG
    consumers:
      - name: syncInsights
        config:
          groupId: group1
        subscribe:
          topic: insights-sync
          fromBeginning: true
        execute: orm.execute(message.query, message.data, {stage:"insights"})
