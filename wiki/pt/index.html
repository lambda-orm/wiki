λORM

O λORM (LambdaORM) é um ORM em TypeScript que executa consultas distribuídas entre diferentes mecanismos de banco de dados: MySQL, MariaDB, PostgreSQL, SQL Server, Oracle, MongoDB e SQLite.

As consultas são escritas como expressões lambda sobre um modelo de domínio independente da infraestrutura. Uma única consulta pode ler ou gravar entidades armazenadas em bancos de dados diferentes — por exemplo, algumas em MySQL, outras em PostgreSQL e outras em MongoDB — e o λORM a divide em uma sentença por fonte e une os resultados.

O mesmo domínio pode ter vários stages (cenários de infraestrutura). Em um stage os dados podem estar distribuídos entre SQL Server, MongoDB e Oracle; em outro, tudo pode estar em um único banco de dados PostgreSQL. Isso permite implementar padrões como CQRS por meio de configuração, sem alterar o código.

Como usar

Forma Pacote Quando usar
Biblioteca Node.js @lambdaorm/lib Executar consultas a partir de uma aplicação Node.js / TypeScript. Veja Uso.
Linha de comando @lambdaorm/cli (comando lambdaorm) Criar um projeto, sincronizar os bancos de dados, importar e exportar dados e executar consultas em um terminal ou em CI. Veja CLI.
Data Gateway Imagem Docker flaviorita/data-gateway Expor esquemas do λORM pela rede: uma API REST, MCP para agentes de IA, uma API WebSocket e uma UI web. Veja Data Gateway.
Cliente Node.js @lambdaorm/client Executar as mesmas consultas a partir do Node.js em um Data Gateway. Veja Clientes. 
npm install @lambdaorm/lib      # the library
npm install -g @lambdaorm/cli   # the lambdaorm command

Nota

Os pacotes sem escopo lambdaorm, lambdaorm-cli e lambdaorm-client-node não são mais mantidos: use os pacotes @lambdaorm/*.

Linguagem de consulta

A consulta a seguir retorna o maior preço de cada categoria de produto, considerando apenas os produtos que atendem ao filtro e as categorias cujo maior preço é superior a 50:

import { orm } from '@lambdaorm/lib'
import { Products } from './northwind/domain/model'

const query = (country: string) => Products
  .filter(p => (p.price > 5 && p.supplier.country == country) || (p.inStock < 3))
  .having(p => max(p.price) > 50)
  .map(p => ({ category: p.category.name, largestPrice: max(p.price) }))
  .sort(p => desc(p.largestPrice))

await orm.init('./lambdaORM.yaml')
// run the query, passing the value of the country parameter
const result = await orm.execute(query, { country: 'ARG' })
await orm.end()

Nesta consulta:

  • filter mantém os produtos cujo preço é maior que 5 e cujo fornecedor está no país informado, assim como aqueles com menos de 3 unidades em estoque.
  • map retorna o nome da categoria e o maior preço. O agrupamento é implícito: os produtos são agrupados por categoria porque max é uma função de agregação.
  • having mantém apenas as categorias cujo maior preço é maior que 50.
  • sort ordena o resultado pelo maior preço, em ordem decrescente.
  • supplier e category são relações: os joins são implícitos.

Include

include retorna uma entidade junto com suas relações na mesma consulta, mesmo quando estão armazenadas em bancos de dados diferentes. Neste exemplo a consulta é escrita como string, uma alternativa à expressão lambda:

import { orm } from '@lambdaorm/lib'

(async () => {
  try {
    await orm.init('./config/northwind.yaml')
    const query = `Orders
      .filter(p => p.id === id)
      .include(p => [
        p.customer.map(p => p.name),
        p.details
          .include(p => p.product
            .include(p => p.category.map(p => p.name))
            .map(p => p.name))
          .map(p => [p.quantity, p.unitPrice])
      ])`
    const result = await orm.execute(query, { id: 102 }, { stage: 'PostgreSQL' })
    console.log(JSON.stringify(result, null, 2))
  } catch (error: any) {
    console.error(error.message)
  } finally {
    await orm.end()
  }
})()

Esquema

O esquema define entidades, enumerações, índices, chaves únicas, valores padrão, restrições, mapeamentos, fontes, stages, listeners e muito mais. Ele é escrito em YAML ou JSON. Condições e ações usam a mesma linguagem de expressões das consultas.

Veja também: esquema | definição | uso | expressões | variáveis de ambiente | composição | listeners | múltiplos stages | múltiplas fontes | mecanismos de banco de dados

Sincronização

O λORM mantém os bancos de dados e o esquema em sincronia, nas duas direções: sincronização | push | pull | fetch | introspect | incorporate

Transações e scripts

  • Transações: orm.transaction executa várias consultas em uma só transação, inclusive entre fontes e stages.
  • Scripts: um caso de uso inteiro (variáveis, condições, laços e várias consultas) em uma só transação e em uma única chamada — a partir do Node.js, da CLI ou do Data Gateway.
