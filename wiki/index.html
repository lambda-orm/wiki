λORM

λORM (LambdaORM) is a TypeScript ORM that runs distributed queries across different database engines: MySQL, MariaDB, PostgreSQL, SQL Server, Oracle, MongoDB and SQLite.

Queries are written as lambda expressions over a domain model that is independent of the infrastructure. A single query can read or write entities stored in different databases — for example, some in MySQL, others in PostgreSQL and others in MongoDB — and λORM splits it into one sentence per source and joins the results.

The same domain can have several stages (infrastructure scenarios). In one stage the data may be spread across SQL Server, MongoDB and Oracle; in another, everything may live in a single PostgreSQL database. This makes it possible to implement patterns such as CQRS through configuration, without changing the code.

See the features for a complete list.

How to use it

Way Package When to use it
Node.js library @lambdaorm/lib Run queries from a Node.js / TypeScript application. See Usage.
Command line @lambdaorm/cli (command lambdaorm) Create a project, synchronize the databases, import and export data, and run queries from a terminal or CI. See CLI.
Data Gateway Docker image flaviorita/data-gateway Expose λORM schemas over the network: a REST API, MCP for AI agents, a WebSocket API and a web UI. See Data Gateway.
Node.js client @lambdaorm/client Run the same queries from Node.js against a Data Gateway. See Clients. 
npm install @lambdaorm/lib      # the library
npm install -g @lambdaorm/cli   # the lambdaorm command

Note

The unscoped packages lambdaorm, lambdaorm-cli and lambdaorm-client-node are no longer maintained: use the @lambdaorm/* packages.

Query language

The following query returns the highest price of each product category, considering only the products that match the filter and the categories whose highest price is above 50:

import { orm } from '@lambdaorm/lib'
import { Products } from './northwind/domain/model'

const query = (country: string) => Products
  .filter(p => (p.price > 5 && p.supplier.country == country) || (p.inStock < 3))
  .having(p => max(p.price) > 50)
  .map(p => ({ category: p.category.name, largestPrice: max(p.price) }))
  .sort(p => desc(p.largestPrice))

await orm.init('./lambdaORM.yaml')
// run the query, passing the value of the country parameter
const result = await orm.execute(query, { country: 'ARG' })
await orm.end()

In this query:

  • filter keeps the products whose price is greater than 5 and whose supplier is in the given country, as well as those with fewer than 3 units in stock.
  • map returns the category name and the highest price. Grouping is implicit: the products are grouped by category because max is an aggregate function.
  • having keeps only the categories whose highest price is greater than 50.
  • sort orders the result by the highest price, in descending order.
  • supplier and category are relations: the joins are implicit.

Include

include returns an entity together with its relations in the same query, even when they are stored in different databases. In this example the query is written as a string, an alternative to the lambda expression:

import { orm } from '@lambdaorm/lib'

(async () => {
  try {
    await orm.init('./config/northwind.yaml')
    const query = `Orders
      .filter(p => p.id === id)
      .include(p => [
        p.customer.map(p => p.name),
        p.details
          .include(p => p.product
            .include(p => p.category.map(p => p.name))
            .map(p => p.name))
          .map(p => [p.quantity, p.unitPrice])
      ])`
    const result = await orm.execute(query, { id: 102 }, { stage: 'PostgreSQL' })
    console.log(JSON.stringify(result, null, 2))
  } catch (error: any) {
    console.error(error.message)
  } finally {
    await orm.end()
  }
})()

Schema

The schema defines entities, enumerations, indexes, unique keys, default values, constraints, mappings, sources, stages, listeners and more. It is written in YAML or JSON. Conditions and actions use the same expression language as queries.

See also: schema | definition | use | expressions | environment variables | composite | listeners | multiple stages | multiple sources | engines

Synchronization

λORM keeps the databases and the schema in step, in both directions: synchronization | push | pull | fetch | introspect | incorporate

Transactions and scripts

  • Transactions: orm.transaction runs several queries in one transaction, also across sources and stages.
  • Scripts: a whole use case (variables, conditions, loops and several queries) in one transaction and in a single call — from Node.js, the CLI or the Data Gateway.

Related projects
