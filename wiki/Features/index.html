Features

An overview of what λORM offers, with links to the pages that describe each feature.

Database engines

  • MySQL, MariaDB, PostgreSQL, SQL Server, Oracle, MongoDB and SQLite (SQLjs).
  • A single query can involve several databases, even of different engines.
  • Engines: the differences between engines (types, empty strings, upsert, …).

Query language

  • Query language based on JavaScript lambda expressions.
  • Queries can be written as JavaScript/TypeScript code or as a string.
  • Select, insert, bulk insert, update and delete clauses.
  • Implicit joins and grouping.
  • Eager loading of relations with include, also across databases.
  • Operators and functions.
  • Query metadata: the parameters, model, constraints and execution plan of a query.

Usage

  • Repositories and custom repositories.
  • Transactions and distributed transactions, across sources and stages.
  • Scripts: a whole use case (variables, conditions, loops and several queries) in one transaction, also over the Data Gateway.
  • Usage examples: a single source, several sources, CQRS and the Node.js client.

Schema

  • Schema configuration that decouples the domain model from the infrastructure.
  • Configuration in JSON or YAML.
  • Mappings between the domain and the infrastructure.
  • Entity inheritance (extends).
  • Environment variables.
  • Indexes, unique keys and constraints.
  • Conditions and actions based on the 3xpr expression engine (expressions).
  • Stages: several infrastructure scenarios for the same domain.
  • Synchronization between the schema and the databases: push, pull, fetch, introspect and incorporate.
  • Listeners and subscribers: awaited, and run in the transaction of the sentence that triggers them.

Performance

  • Bulk insert.
  • High-performance queries.
  • Connection pooling.

Tools and clients

  • TypeScript and JavaScript support.
  • CLI (npm i -g @lambdaorm/cli, command lambdaorm).
  • Data Gateway (Docker image flaviorita/data-gateway):
    • a REST API, MCP for AI agents and a WebSocket API, with several schemas per instance;
    • credentials with permissions, audit of writes, metrics and health checks;
    • a web UI: explorer, entity forms, saved queries and diagrams of the domain.
  • Clients:
    • Node.js client (@lambdaorm/client, REST or WebSocket);
    • other languages: generate a client from the Data Gateway's OpenAPI 3 document.
