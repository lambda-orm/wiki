Einfügen

Diese Seite zeigt, wie Sie Datensätze einfügen: mit allen Eigenschaften der Entität oder nur einigen davon, zusammen mit verbundenen Entitäten (include), und wie Sie in einem Schritt einfügen oder aktualisieren (upsert). Wie Sie viele Datensätze auf einmal einfügen, erfahren Sie unter Bulk Insert. Das gezeigte SQL ist das für MySQL erzeugte, sofern nicht anders angegeben.

Eine Abfrage beruht sowohl auf dem Ausdruck als auch auf dem Schema. Wenn Sie die einzufügenden Eigenschaften nicht angeben, werden alle Eigenschaften der Entität eingefügt. Wie jede Eigenschaft in jeder Quelle gespeichert wird (Tabellen- und Spaltennamen), wird durch das Mapping dieser Quelle im Schema aufgelöst.

Alle Eigenschaften einfügen

Wenn die Eigenschaften nicht angegeben sind, müssen die übergebenen Daten ein Objekt mit den Eigenschaften der Entität sein.

Lambda:

Categories.insert()

SQL-Ergebnis:

INSERT INTO Categories(CategoryName,Description) VALUES(?,?)

Der Primärschlüssel id wird nicht eingefügt, da er automatisch hochgezählt wird (Auto-Increment): Die Datenbank erzeugt ihn.

Einige Eigenschaften einfügen

Nur die angegebenen Eigenschaften werden eingefügt. Hier ist name eine Variable der an die Abfrage übergebenen Daten.

Lambda:

Categories.insert({ name: name })

SQL-Ergebnis:

INSERT INTO Categories(CategoryName) VALUES(?)

Einfügen mit include

Um ein Objekt zusammen mit seinen verbundenen Objekten einzufügen, binden Sie die Beziehung ein. Dieses Beispiel fügt eine Bestellung und ihre Positionen ein; der Schlüssel der neuen Bestellung wird jeder Position zugewiesen.

Lambda:

Orders.insert().include(p => p.details)

SQL-Ergebnis:

-- the order
INSERT INTO Orders(CustomerID,EmployeeID,OrderDate,RequiredDate,ShippedDate,ShipVia,Freight,ShipName,ShipAddress,ShipCity,ShipRegion,ShipPostalCode,ShipCountry)
VALUES(?,?,?,?,?,?,?,?,?,?,?,?,?)

-- each detail of the order
INSERT INTO `Order Details`(OrderID,ProductID,UnitPrice,Quantity,Discount)
VALUES(?,?,?,?,?)

Upsert

upsert() fügt den Datensatz ein oder aktualisiert ihn, falls bereits ein Datensatz mit demselben Primärschlüssel existiert. Es wird wie ein Insert geschrieben: upsert() mit allen Eigenschaften oder mit den angegebenen Eigenschaften. Die Entität benötigt einen Primärschlüssel, und die Daten müssen ihn enthalten (ein Auto-Increment-Schlüssel ist hier daher wenig nützlich).

Lambda:

// inserts the country, or updates it when one with the same iso3 exists
Countries.upsert()

await orm.execute('Countries.upsert()', { iso3: 'ARG', name: 'Argentine' }) // inserted
await orm.execute('Countries.upsert()', { iso3: 'ARG', name: 'Argentina' }) // updated: the same row

SQL-Ergebnis:

-- MySQL / MariaDB
INSERT INTO Countries(iso3,name) VALUES(?,?) ON DUPLICATE KEY UPDATE name = VALUES(name)

-- PostgreSQL
INSERT INTO Countries(iso3,name) VALUES($1,$2)
ON CONFLICT (iso3) DO UPDATE SET name = EXCLUDED.name

-- SQL Server
MERGE INTO Countries WITH (HOLDLOCK) AS t
USING (SELECT 1 AS x) AS s
ON t.iso3 = @iso3
WHEN MATCHED THEN UPDATE SET name = @name
WHEN NOT MATCHED THEN INSERT (iso3,name) VALUES (@iso3,@name);

-- Oracle
MERGE INTO Countries t
USING (SELECT 1 FROM DUAL) s
ON (t.iso3 = :iso3)
WHEN MATCHED THEN UPDATE SET name = :name
WHEN NOT MATCHED THEN INSERT (iso3,name) VALUES (:iso3,:name)

Upsert wird auf PostgreSQL, MySQL, MariaDB, SQL Server und Oracle unterstützt (die beiden letzteren mit MERGE, ab @lambdaorm/lib 3.5.0).

Warnung

Auf MongoDB schlägt upsert mit dem Fehler „not supported yet“ fehl. SQLite (SQL.js) unterstützt es ebenfalls nicht.

Wenn der Schlüssel generiert wird (Auto-Increment) und nicht mitgesendet wird, fügt das Upsert ein. Auf SQL Server wird die Identity-Spalte nie eingefügt (die Datenbank erzeugt sie) und OUTPUT INSERTED gibt sie zurück; das MERGE von Oracle kann keine Werte zurückgeben und liefert daher den gesendeten Schlüssel.

Auch ein Update mit include einer Kompositionsbeziehung verwendet Upsert, um die Kindelemente zu speichern.

Codebeispiel

Fügt eine Bestellung mit zwei Positionen ein und gibt die ID der neuen Bestellung aus.

import { orm } from '@lambdaorm/lib'
import { Orders } from './domain/model' // model generated by `lambdaorm build`

(async () => {
    try {
        await orm.init('./lambdaORM.yaml')
        const order = {
            customerId: 'VINET',
            employeeId: 5,
            orderDate: '1996-07-03T22:00:00.000Z',
            requiredDate: '1996-07-31T22:00:00.000Z',
            shippedDate: '1996-07-15T22:00:00.000Z',
            shipViaId: 3,
            freight: 32.38,
            name: 'Vins et alcools Chevalier',
            address: '59 rue de l-Abbaye',
            city: 'Reims',
            postalCode: '51100',
            country: 'France',
            // orderId is assigned from the new order
            details: [
                { productId: 11, unitPrice: 14, quantity: 12, discount: 10 },
                { productId: 42, unitPrice: 9.8, quantity: 10, discount: 10 }
            ]
        }
        const query = () => Orders.insert().include(p => p.details)
        // returns the id of the order created
        const result = await orm.execute(query, order)
        console.log(JSON.stringify(result))
    } catch (error: any) {
        console.error(error.stack)
    } finally {
        // releases the connections
        await orm.end()
    }
})()
