λORM

λORM (LambdaORM) ist ein TypeScript-ORM, das verteilte Abfragen über verschiedene Datenbank-Engines hinweg ausführt: MySQL, MariaDB, PostgreSQL, SQL Server, Oracle, MongoDB und SQLite.

Abfragen werden als Lambda-Ausdrücke über ein Domänenmodell geschrieben, das von der Infrastruktur unabhängig ist. Eine einzige Abfrage kann Entitäten lesen oder schreiben, die in verschiedenen Datenbanken gespeichert sind – zum Beispiel einige in MySQL, andere in PostgreSQL und wieder andere in MongoDB –, und λORM zerlegt sie in eine Anweisung pro Quelle und führt die Ergebnisse zusammen.

Dieselbe Domäne kann mehrere Stages (Infrastruktur-Szenarien) haben. In einem Stage können die Daten auf SQL Server, MongoDB und Oracle verteilt sein; in einem anderen kann alles in einer einzigen PostgreSQL-Datenbank liegen. So lassen sich Muster wie CQRS per Konfiguration umsetzen, ohne den Code zu ändern.

Eine vollständige Liste finden Sie unter Funktionen.

Verwendung

Weg Paket Wann verwenden
Node.js-Bibliothek @lambdaorm/lib Abfragen aus einer Node.js-/TypeScript-Anwendung ausführen. Siehe Verwendung.
Kommandozeile @lambdaorm/cli (Befehl lambdaorm) Ein Projekt erstellen, die Datenbanken synchronisieren, Daten importieren und exportieren und Abfragen aus einem Terminal oder in CI ausführen. Siehe CLI.
Data Gateway Docker-Image flaviorita/data-gateway λORM-Schemas über das Netzwerk bereitstellen: eine REST API, MCP für KI-Agenten, eine WebSocket API und eine Web-UI. Siehe Data Gateway.
Node.js-Client @lambdaorm/client Dieselben Abfragen aus Node.js gegen ein Data Gateway ausführen. Siehe Clients. 
npm install @lambdaorm/lib      # the library
npm install -g @lambdaorm/cli   # the lambdaorm command

Hinweis

Die Pakete ohne Scope lambdaorm, lambdaorm-cli und lambdaorm-client-node werden nicht mehr gepflegt: Verwenden Sie die Pakete @lambdaorm/*.

Abfragesprache

Die folgende Abfrage liefert den höchsten Preis jeder Produktkategorie, wobei nur die Produkte berücksichtigt werden, die dem Filter entsprechen, und nur die Kategorien, deren höchster Preis über 50 liegt:

import { orm } from '@lambdaorm/lib'
import { Products } from './northwind/domain/model'

const query = (country: string) => Products
  .filter(p => (p.price > 5 && p.supplier.country == country) || (p.inStock < 3))
  .having(p => max(p.price) > 50)
  .map(p => ({ category: p.category.name, largestPrice: max(p.price) }))
  .sort(p => desc(p.largestPrice))

await orm.init('./lambdaORM.yaml')
// run the query, passing the value of the country parameter
const result = await orm.execute(query, { country: 'ARG' })
await orm.end()

In dieser Abfrage:

  • filter behält die Produkte, deren Preis größer als 5 ist und deren Lieferant im angegebenen Land ansässig ist, sowie diejenigen mit weniger als 3 Einheiten auf Lager.
  • map liefert den Kategorienamen und den höchsten Preis. Die Gruppierung ist implizit: Die Produkte werden nach Kategorie gruppiert, weil max eine Aggregatfunktion ist.
  • having behält nur die Kategorien, deren höchster Preis größer als 50 ist.
  • sort sortiert das Ergebnis absteigend nach dem höchsten Preis.
  • supplier und category sind Beziehungen: Die Joins sind implizit.

Include

include liefert eine Entität zusammen mit ihren Beziehungen in derselben Abfrage, auch wenn diese in verschiedenen Datenbanken gespeichert sind. In diesem Beispiel wird die Abfrage als String geschrieben, eine Alternative zum Lambda-Ausdruck:

import { orm } from '@lambdaorm/lib'

(async () => {
  try {
    await orm.init('./config/northwind.yaml')
    const query = `Orders
      .filter(p => p.id === id)
      .include(p => [
        p.customer.map(p => p.name),
        p.details
          .include(p => p.product
            .include(p => p.category.map(p => p.name))
            .map(p => p.name))
          .map(p => [p.quantity, p.unitPrice])
      ])`
    const result = await orm.execute(query, { id: 102 }, { stage: 'PostgreSQL' })
    console.log(JSON.stringify(result, null, 2))
  } catch (error: any) {
    console.error(error.message)
  } finally {
    await orm.end()
  }
})()

Schema

Das Schema definiert Entitäten, Enumerationen, Indizes, eindeutige Schlüssel, Standardwerte, Constraints, Mappings, Quellen, Stages, Listener und mehr. Es wird in YAML oder JSON geschrieben. Bedingungen und Aktionen verwenden dieselbe Ausdruckssprache wie Abfragen.

Siehe auch: Schema | Definition | Verwendung | Ausdrücke | Umgebungsvariablen | Composite | Listener | mehrere Stages | mehrere Quellen | Datenbank-Engines

Synchronisierung

λORM hält die Datenbanken und das Schema in beide Richtungen synchron: Synchronisierung | push | pull | fetch | introspect | incorporate

Transaktionen und Skripte

  • Transaktionen: orm.transaction führt mehrere Abfragen in einer Transaktion aus, auch über Quellen und Stages hinweg.
  • Skripte: ein ganzer Anwendungsfall (Variablen, Bedingungen, Schleifen und mehrere Abfragen) in einer Transaktion und in einem einzigen Aufruf – aus Node.js, der CLI oder dem Data Gateway.
