Komposit-Beispiel

Diese Seite zeigt eine Komposit-Entität, Orders.details, die auf einem Stage in MongoDB und auf einem anderen in PostgreSQL gespeichert wird, und wie dieselbe Abfrage auf beiden dasselbe Ergebnis liefert.

Ein Punkt im Namen einer Entität definiert eine Komposit-Entität: Orders.details ist eine Komposit-Entität von Orders.

Ist die Quelle NoSQL, werden die Positionen innerhalb der Bestellung in einer einzigen Collection gespeichert; ist die Quelle relational, werden sie in separaten Tabellen gespeichert. In der Domäne werden sie unabhängig vom Typ der Quelle gleich behandelt, sodass das Modell nicht von der Persistenztechnologie abhängt.

Komposit-Entität

In diesem Beispiel ist Orders.details eine Komposit-Entität von Orders. Ihre Beziehung order mit target: details erzeugt die Komposit-Beziehung details in Orders.

Teil des Schemas, in dem die Komposit-Entität definiert ist:

domain:  
  entities:
...  
  - name: Orders
    primaryKey: [id]
    indexes:
    - name: orderDate
      fields: [orderDate]
    properties:
    - name: id
      type: integer
      required: true
      autoIncrement: true
    - name: customerId
      required: true
      length: 5
    - name: orderDate
      type: dateTime 
  - name: Orders.details
    primaryKey: [orderId, productId]
    properties:
    - name: orderId
      required: true
      type: integer
    - name: productId
      required: true
      type: integer
    - name: unitPrice
      type: decimal
    - name: quantity
      type: decimal
    relations:
    - name: order
      from: orderId
      entity: Orders
      to: id
      target: details
...

Komposit-Entität in verschiedenen Quellen

Dieses Beispiel zeigt, wie eine Komposit-Entität in verschiedenen Quellen gespeichert wird. Auf dem Stage default werden Orders und Orders.details in MongoDB gespeichert; auf dem Stage insights in PostgreSQL.

Teil des Schemas, in dem die Stages konfiguriert sind:

...
  stages:
  - name: default
    sources:
    - name: Catalog
      condition: entity.in(["Categories","Products"])
    - name: Crm
      condition: entity.in(["Address","Customers"])
    - name: Ordering
      condition: entity.in(["Orders","Orders.details"])
  - name: insights
    sources:
    - name: Insights
...
