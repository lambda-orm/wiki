Pull

This page explains pull, which updates the schema file with the structure of the sources (databases) of a stage: what it keeps, the CLI command lambdaorm pull and the orm.stage.pull() method.

What pull keeps

Pull reads the tables and columns of the databases and merges them into the schema: new tables become entities, new columns become properties, and the mappings are updated. Pull does not change the databases. By default it also removes from the schema the entities, properties and relations that are no longer in the database (orm.stage.pull({ stage, removeEntities: false, removeProperties: false, removeRelations: false }) keeps them). It can be run on an existing schema: what was written by hand is kept, for example

  • relation names chosen by hand and weak relations between sources (which have no foreign key in the database),
  • application.listeners,
  • infrastructure.stages.

Columns named with reserved words (for example order) are supported.

CLI

The pull command updates the schema file (lambdaORM.yaml in this example) with the structure of the databases of the stage:

lambdaorm pull
Option Description
-w, --workspace Folder of the project (default: the current folder).
-s, --stage Name of the stage (default: the first stage).
-e, --envfile File of environment variables to read.

Pull also writes, in the orm_state folder, the model of the stage and the DDL of the pulled structure, in one folder per source. The DDL is a record: it is not executed.

Files created:

├── orm_state
│   ├── default-model.json
│   └── default
│       └── V240501212640__pull.sql

Node

orm.stage.pull() updates the schema file with the structure of the databases of the stage:

import { Orm } from '@lambdaorm/lib'
(async () => {
    const orm = new Orm()
    try {
        await orm.init('./lambdaORM.yaml')
        await orm.stage.pull({ stage: 'default' })
    } catch (e) {
        console.log(e)
    } finally {
        await orm.end()
    }
})()
