λORM

λORM (LambdaORM) es un ORM de TypeScript que ejecuta consultas distribuidas sobre distintos motores de base de datos: MySQL, MariaDB, PostgreSQL, SQL Server, Oracle, MongoDB y SQLite.

Las consultas se escriben como expresiones lambda sobre un modelo de dominio independiente de la infraestructura. Una sola consulta puede leer o escribir entidades almacenadas en distintas bases de datos —por ejemplo, unas en MySQL, otras en PostgreSQL y otras en MongoDB— y λORM la divide en una sentencia por fuente y une los resultados.

Un mismo dominio puede tener varios stages (escenarios de infraestructura). En un stage los datos pueden estar repartidos entre SQL Server, MongoDB y Oracle; en otro, todo puede residir en una única base de datos PostgreSQL. Esto permite implementar patrones como CQRS mediante configuración, sin cambiar el código.

Cómo usarlo

Forma Paquete Cuándo usarla
Librería de Node.js @lambdaorm/lib Ejecutar consultas desde una aplicación Node.js / TypeScript. Véase Uso.
Línea de comandos @lambdaorm/cli (comando lambdaorm) Crear un proyecto, sincronizar las bases de datos, importar y exportar datos y ejecutar consultas desde una terminal o desde CI. Véase CLI.
Data Gateway Imagen Docker flaviorita/data-gateway Exponer esquemas de λORM a través de la red: una API REST, MCP para agentes de IA, una API WebSocket y una UI web. Véase Data Gateway.
Cliente de Node.js @lambdaorm/client Ejecutar las mismas consultas desde Node.js contra un Data Gateway. Véase Clientes. 
npm install @lambdaorm/lib      # the library
npm install -g @lambdaorm/cli   # the lambdaorm command

Nota

Los paquetes sin scope lambdaorm, lambdaorm-cli y lambdaorm-client-node ya no se mantienen: hay que usar los paquetes @lambdaorm/*.

Lenguaje de consultas

La siguiente consulta devuelve el precio más alto de cada categoría de productos, considerando solo los productos que cumplen el filtro y las categorías cuyo precio más alto supera 50:

import { orm } from '@lambdaorm/lib'
import { Products } from './northwind/domain/model'

const query = (country: string) => Products
  .filter(p => (p.price > 5 && p.supplier.country == country) || (p.inStock < 3))
  .having(p => max(p.price) > 50)
  .map(p => ({ category: p.category.name, largestPrice: max(p.price) }))
  .sort(p => desc(p.largestPrice))

await orm.init('./lambdaORM.yaml')
// run the query, passing the value of the country parameter
const result = await orm.execute(query, { country: 'ARG' })
await orm.end()

En esta consulta:

  • filter conserva los productos cuyo precio es mayor que 5 y cuyo proveedor está en el país indicado, así como los que tienen menos de 3 unidades en stock.
  • map devuelve el nombre de la categoría y el precio más alto. La agrupación es implícita: los productos se agrupan por categoría porque max es una función de agregación.
  • having conserva solo las categorías cuyo precio más alto es mayor que 50.
  • sort ordena el resultado por el precio más alto, en orden descendente.
  • supplier y category son relaciones: los joins son implícitos.

Include

include devuelve una entidad junto con sus relaciones en la misma consulta, incluso cuando están almacenadas en distintas bases de datos. En este ejemplo la consulta se escribe como una cadena, una alternativa a la expresión lambda:

import { orm } from '@lambdaorm/lib'

(async () => {
  try {
    await orm.init('./config/northwind.yaml')
    const query = `Orders
      .filter(p => p.id === id)
      .include(p => [
        p.customer.map(p => p.name),
        p.details
          .include(p => p.product
            .include(p => p.category.map(p => p.name))
            .map(p => p.name))
          .map(p => [p.quantity, p.unitPrice])
      ])`
    const result = await orm.execute(query, { id: 102 }, { stage: 'PostgreSQL' })
    console.log(JSON.stringify(result, null, 2))
  } catch (error: any) {
    console.error(error.message)
  } finally {
    await orm.end()
  }
})()

Esquema

El esquema define entidades, enumeraciones, índices, claves únicas, valores por defecto, restricciones, mappings, fuentes, stages, listeners y más. Se escribe en YAML o JSON. Las condiciones y acciones usan el mismo lenguaje de expresiones que las consultas.

Véase también: esquema | definición | uso | expresiones | variables de entorno | composición | listeners | múltiples stages | múltiples fuentes | motores de base de datos

Sincronización

λORM mantiene las bases de datos y el esquema sincronizados, en ambas direcciones: sincronización | push | pull | fetch | introspect | incorporate

Transacciones y scripts

  • Transacciones: orm.transaction ejecuta varias consultas en una sola transacción, también entre fuentes y stages.
  • Scripts: un caso de uso completo (variables, condiciones, bucles y varias consultas) en una sola transacción y en una única llamada, desde Node.js, la CLI o el Data Gateway.
