Transports

The gateway has four transports. Each one listens on its own port, only when the port is configured (Configuration), and each one reaches every schema by its route.

Transport What it is Routes of the schema iot/v1 Routes of the gateway
http REST API, OpenAPI 3 POST /iot/v1/execute, GET /iot/v1/entities, … /ping, /health, /metrics, /version, /schemas, /doc, /api-docs, /ui
mcpHttp MCP for AI agents POST/GET/DELETE /iot/v1/mcp (Streamable HTTP); GET /iot/v1/sse + POST /iot/v1/messages?sessionId= (HTTP+SSE) GET /status
mcpWebSocket MCP over WebSocket upgrade at /iot/v1/mcp GET /status, /asyncapi
webSocket JSON-RPC API with notifications connection to ws://host:port/iot/v1 connection to the root: general.* and gateway.schemas; /asyncapi
  • {basePath} (transports.<t>.basePath) goes before every route: with basePath: /data-gateway, /data-gateway/iot/v1/execute and /data-gateway/ui/.
  • With a single schema at the root, its routes have no prefix (/execute, /mcp, ws://host:port/).
  • A schema that is not exposed on a transport (schemas[].transports) answers 404 there. A schema that is not ready answers 503 with the reason.
  • Each transport authenticates every request (or the WebSocket upgrade) with the effective authentication of the schema (Security).

http

The REST API: every operation of λORM on a schema (queries, scripts, the schema, stages), plus the routes of the gateway. JSON in and out. Methods and examples in REST API.

transports:
  http:
    port: 8080
    basePath: /data-gateway   # optional
    swagger: { enabled: true }   # /doc and /api-docs (Swagger UI, OpenAPI 3)
    ui: { enabled: true }        # the web UI at /ui
  • GET /doc (and /api-docs) serves Swagger UI with the OpenAPI document. Its Authorize button asks for the credential as the schemas are configured: an API key in its header, a bearer token or a user and password.
  • /ping, /health and /metrics need no credential (Kubernetes probes, Prometheus).
  • The rate limit (rateLimit) applies to this transport only.

mcpHttp

Model Context Protocol for AI agents: a server per schema, with a tool per operation. See MCP.

transports:
  mcpHttp:
    port: 8081
    legacySse: true    # also the older HTTP+SSE transport, for older clients
    stateful: false    # stateless: any replica answers any request, no session affinity needed
Route Protocol Clients
POST/GET/DELETE {basePath}/{schema}/mcp Streamable HTTP Claude Code (--transport http), current clients
GET {basePath}/{schema}/sse + POST {basePath}/{schema}/messages?sessionId=<id> HTTP+SSE (deprecated), with legacySse: true older clients
GET {basePath}/status the state, the schemas and the open SSE sessions operations

The credential goes in every request (Streamable HTTP) or in the GET and every POST (SSE). HTTP+SSE keeps a session in memory: with several replicas it needs session affinity.

mcpWebSocket

The same MCP servers over WebSocket. It is not a standard MCP transport: it is offered for clients and gateways that support it on their own; most clients use mcpHttp.

transports:
  mcpWebSocket:
    port: 8082
    maxConnections: 100

The connection is an upgrade at {basePath}/{schema}/mcp, authenticated in the handshake (without a credential it answers 401 and closes). The messages are JSON-RPC 2.0 with the MCP methods (initialize, ping, tools/list, tools/call, resources/*, …). GET {basePath}/status and GET {basePath}/asyncapi (the AsyncAPI document) are plain HTTP.

webSocket

A JSON-RPC 2.0 API over one persistent connection, with the same operations as REST, plus notifications that REST cannot give: the end of a queued execution and the changes of state of the schema. See WebSocket API.

transports:
  webSocket:
    port: 8083
    maxConnections: 100
    asyncapi: { enabled: true }   # GET /asyncapi, /asyncapi.json
